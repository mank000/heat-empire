# Империя тепла

Адаптивный лендинг на Django 5.2, HTML и CSS. Макеты главной в Figma: [1440 px](https://www.figma.com/design/bbgufdPCw8sVnFvTucYKmh/?node-id=4232-3293), [768 px](https://www.figma.com/design/bbgufdPCw8sVnFvTucYKmh/?node-id=4238-655) и [368 px](https://www.figma.com/design/bbgufdPCw8sVnFvTucYKmh/?node-id=4240-1694).

## Запуск через Docker

```sh
docker compose up --build -d --wait
docker compose exec web python manage.py createsuperuser
```

Главная откроется по адресу http://127.0.0.1:8000/, админка — по адресу http://127.0.0.1:8000/admin/.
Если порт занят, задай другой, например `HEAT_PORT=8125 docker compose up -d --wait`.
Миграции выполняются при старте. Контакты, юридические страницы, заявки и учётные записи хранятся в томе `site_data`.
Если имя каталога содержит только кириллицу и пробелы, укажи имя проекта явно, например `docker compose -p heat-empire up --build -d --wait`.

## Запуск без Docker

Нужен Python 3.10 или новее.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
export DJANGO_DEBUG=1 DJANGO_SECRET_KEY=local-development-only
python manage.py migrate
python manage.py runserver
```

## Редактирование контактов

При запуске без Docker создай учётную запись командой `python manage.py createsuperuser`.
Откройте http://127.0.0.1:8000/admin/ и выберите **Настройки сайта → Контакты сайта**.
Телефон и адрес из макета уже заполнены. Укажите полные ссылки для Telegram, WhatsApp и MAX.
Пустое поле оставляет соответствующую иконку без ссылки.

## Редактирование политики и реквизитов

Открой **Настройки сайта → Юридические страницы** в админке. Миграция создаёт две записи: «Политика конфиденциальности» и «Реквизиты компании». Вставь утверждённый текст и сохрани запись. Сайт покажет новый текст сразу. Ссылки на обе страницы находятся в подвале, а ссылка на политику также доступна в обеих формах заявки.

## Запуск на сервере без домена

Скопируй `.env.example` в `.env`, оставь `SITE_DOMAIN` пустым и задай `DJANGO_SECRET_KEY` случайным значением из `openssl rand -hex 32`. При необходимости поменяй `HEAT_PORT`. Docker Compose читает `.env` автоматически. При запуске Django напрямую задай переменные через `export`.

Запусти на сервере базовый Compose. Он поднимет Gunicorn, применит миграции и откроет сайт на `127.0.0.1` сервера.

```sh
docker compose up --build -d --wait
```

Для просмотра с другого компьютера открой SSH-туннель, подставив свой сервер и порт. Затем открой http://127.0.0.1:8000/ в браузере.

```sh
ssh -N -L 8000:127.0.0.1:8000 user@server-ip
```

## Публикация

Направь DNS домена на сервер, открой входящие TCP-порты 80 и 443 и установи Docker Compose 2.24.4 или новее.
Скопируй `.env.example` в `.env` и укажи `SITE_DOMAIN` без схемы и порта. Для `DJANGO_SECRET_KEY` сгенерируй случайный ключ командой `openssl rand -hex 32` и сохрани его в `.env`.

```sh
docker compose -f compose.yaml -f compose.prod.yaml up --build -d --wait
docker compose -f compose.yaml -f compose.prod.yaml exec web python manage.py createsuperuser
```

Caddy получает и обновляет сертификаты. Gunicorn доступен внутри сети Compose.
Django работает с выключенным режимом отладки, защищёнными cookies и версионированной статикой. SQLite рассчитана на один экземпляр приложения. Том `site_data` нужно сохранять при обновлениях. Команда `docker compose down -v` удаляет тома.
HSTS действует на домен сайта. Включение HSTS для всех поддоменов и добавление домена в preload-список браузеров требуют отдельной проверки домена.

Чтобы сделать согласованную резервную копию базы работающего сайта, выполни команду ниже и сохрани файл вне сервера.

```sh
docker compose -f compose.yaml -f compose.prod.yaml exec -T web python /app/backup.py > heat-empire-backup.sqlite3
```

## Текущий объём

- На телефонах сравнение, этапы работ и кейсы листаются горизонтально внутри своих блоков.
- Фотографии и иконки взяты из экспорта Figma. Для заголовков используется Fira Sans Extra Condensed из Impery. Остальные шрифты из макета, TikTok Sans и Manrope, хранятся локально вместе с лицензиями.
- Заявки из формы на главной и модального окна появляются в админке в разделе **Настройки сайта → Заявки на расчёт**. Новые заявки отображаются первыми.

## Telegram-бот

В `.env` задай `TELEGRAM_BOT_TOKEN` от BotFather, случайный `TELEGRAM_ACCESS_PIN` из 8–32 цифр и стойкий `DJANGO_SECRET_KEY` (например, результат `openssl rand -hex 32`). Передавай PIN только тем, кто будет получать уведомления о заявках. После смены PIN сотрудникам нужно ввести новый код.

```sh
docker compose -p heat-empire --profile bot up --build -d --wait
```

На публичном сервере добавь к этой команде `-f compose.yaml -f compose.prod.yaml` после `docker compose`. Бот получает обновления через Telegram API. Для него не нужен домен. Запускай один экземпляр сервиса `bot` для одного токена и отключи ранее настроенный webhook, если он есть.

- `/start` подписывает на общую рассылку и запрашивает PIN для уведомлений о заявках. `/stop` отключает подписку и доступ к уведомлениям.
- В админке открой **Настройки сайта → Рассылки Telegram**, создай черновик, затем выбери его в списке и выполни действие «Поставить выбранные черновики в очередь рассылки». Сообщение будет отправлено активным подписчикам. В списке видны результаты отправки.
- Уведомления о новых заявках содержат номер заявки. Имя и телефон клиента доступны в админке. Очередь хранится в базе. При сетевом сбое бот повторит отправку, поэтому в редких случаях сообщение может прийти дважды.
